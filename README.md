# Звукоряд — рейтинг музыкальных релизов

Сайт, где слушатели и критики оценивают альбомы, EP и синглы по пяти критериям и пишут рецензии.
Итоговая оценка — от 6 до 90 баллов.

## Функционал

| Раздел | Что умеет |
|---|---|
| **Главная** | новые релизы, лучшее за месяц, свежие рецензии, счётчики |
| **Каталог релизов** | фильтры по типу / жанру / году, сортировка (новые, по оценке слушателей/критиков, по популярности), пагинация |
| **Страница релиза** | обложка, треклист, оценки слушателей и критиков отдельно, разбор средних по каждому критерию, форма оценки с живым калькулятором, рецензии с лайками (сортировка «популярные / новые») |
| **Топ** | за месяц / год / всё время, по типу релиза, по слушателям или критикам |
| **Исполнители** | каталог с поиском, страница артиста с дискографией по типам, средним баллом и лучшим релизом |
| **Профиль** | статистика (кол-во оценок, средний балл, лайки), гистограмма оценок, лента оценок; настройки аватара/описания и смена пароля |
| **Предложить релиз** | любой пользователь отправляет релиз → он попадает на модерацию |
| **Поиск** | по релизам, исполнителям и пользователям |
| **Админка** `/admin` | модерация заявок, CRUD релизов и исполнителей, смена ролей (слушатель / критик / админ), удаление оценок |

### Система оценки

Четыре критерия от 1 до 10 — **Рифмы и образы**, **Структура и ритмика**, **Реализация стиля**,
**Индивидуальность и харизма** — складываются и умножаются на 1.4 (максимум 56).
Пятый критерий **Атмосфера и вайб** — множитель от ×1.00 до ×1.61:

```
оценка = round((R + S + St + I) × 1.4 × (1 + (V − 1) / 9 × 0.607))   // 6…90
```

Формула в `app/scoring.py` и продублирована в `app/static/js/app.js` для живого калькулятора.

## Архитектура

```
music-rating/
├── wsgi.py                 точка входа (gunicorn wsgi:app)
├── render.yaml             Blueprint для Render: веб-сервис + PostgreSQL
├── requirements.txt
├── app/
│   ├── __init__.py         фабрика create_app(), фильтры шаблонов, обработчики ошибок
│   ├── config.py           настройки из переменных окружения
│   ├── extensions.py       SQLAlchemy, Flask-Login, CSRF
│   ├── models.py           User, Artist, Release, Review, ReviewLike
│   ├── scoring.py          критерии и формула оценки
│   ├── forms.py            WTForms-формы с валидацией
│   ├── bootstrap.py        создание админа из env, демо-данные
│   ├── cli.py              flask create-admin / seed / recalc
│   ├── utils.py            slugify (кириллица → латиница), склонения, декоратор admin_required
│   ├── views/              blueprints: main, auth, releases, artists, users, admin, api
│   ├── templates/          Jinja2-шаблоны
│   └── static/             CSS (тёмная/светлая тема), JS (калькулятор, лайки)
└── tests/                  pytest
```

**Стек:** Python 3.12, Flask 3, SQLAlchemy 2, PostgreSQL (на Render) / SQLite (локально), Gunicorn.
Серверный рендеринг + немного ванильного JS — без сборки фронтенда.

**Модель данных:**

- `User` — роль `user` | `critic` | `admin`. Оценки критиков и админов идут в «оценку критиков».
- `Artist` → много `Release`.
- `Release` — статус `published` | `pending` | `rejected`; хранит денормализованные
  `user_score / user_count / critic_score / critic_count`, которые пересчитываются (`recalc()`)
  при каждом изменении оценок — поэтому сортировка и топы работают одним простым запросом.
- `Review` — одна на пару (пользователь, релиз): 5 баллов, итог, текст, счётчик лайков.
- `ReviewLike` — лайк рецензии (составной первичный ключ).

**Безопасность:** хэширование паролей (werkzeug), CSRF на всех POST-формах и AJAX,
защита от open redirect после логина, secure-cookies на Render, админка закрыта `before_request`.

`admin` / `admin12345` и демо-данные (вымышленные артисты). Тесты: `pytest`.

## Деплой на Render

1. Запушьте репозиторий на GitHub.
2. Render → **New → Blueprint** → выберите репозиторий. Render прочитает `render.yaml`
   и создаст веб-сервис и базу PostgreSQL.
3. Заполните переменные, которые запросит Render: `ADMIN_USERNAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`
   (под этим логином вы получите доступ к `/admin`). `SECRET_KEY` и `DATABASE_URL` подставятся сами.
4. Дождитесь деплоя — таблицы и демо-данные создадутся при первом старте.
   Чтобы не заливать демо-данные, поставьте `SEED_DEMO=0` до первого запуска.

**Особенности бесплатного тарифа Render:**

- Веб-сервис засыпает после ~15 минут без запросов, первый заход после сна — около минуты.
- Бесплатная PostgreSQL удаляется через 30 дней. Для долгой жизни перейдите на платный план
  или укажите в `DATABASE_URL` внешнюю базу (Neon, Supabase и т.п.) — код поддерживает любой Postgres.
- Диск эфемерный, поэтому обложки хранятся ссылками (`cover_url`), а не файлами.
